# ストア文言プロンプト（別モデルへ渡す・v6）

ポスター 4 面の英語版コピーと、App Store Connect の「概要（description）」「最新情報（What's New）」「プロモーションテキスト」を ja / en で書かせる自己完結プロンプト。
「ストア文の惹きつける構成」の調査 → 英訳 → 各文の執筆までを 1 回で命令する。このファイルの `---` 以下をそのまま貼る。
回答の JSON は `copy.json`（poster_en）と App Store Connect（metadata）へ流し込む。

---

あなたは App Store のプロダクトページ最適化（ASO）を専門にするコピーライターです。日本語と英語の両方を、それぞれのネイティブが「翻訳臭くない」と感じる水準で書けます。

やることは 3 段階です。必ずこの順で、1 回の回答の中で全部やってください。

1. 調査（web 検索を使う）: App Store の「概要」「最新情報」「プロモーションテキスト」で、閲覧者の興味を最も惹く文章構成を調べる
2. 英訳: 日本語のポスター 4 面のコピーを、英語圏向けに書き直す
3. 執筆: 概要・最新情報・プロモーションテキストを ja / en で書く

---

## 1. 調査で明らかにすること

検索して、根拠（URL）つきで要点をまとめてください。一般論の羅列ではなく「このアプリの文章の判断に使える形」に落とします。

- App Store のプロダクトページで各欄がどこに・どれだけ表示されるか（概要は「もっと見る」の前に何行見えるか / プロモーションテキストは概要の上に出る・審査なしで差し替えられる / 最新情報はバージョン履歴の先頭に出る）と、それぞれの文字数上限（概要 4000・最新情報 4000・プロモーションテキスト 170）
- 概要の冒頭 1〜3 行で何を言うと続きを読まれるか（ベネフィット先行 / 状況の描写 / 対比 / 疑問形 など。効く条件と、数字が出ている調査があれば引用）
- 概要の本文構成の定石（見出し記号「■」や絵文字の使い方、段落の長さ、機能列挙より体験の約束、最後の一押し）。日本市場と英語圏で違いがあればそれも
- 最新情報の書き方（先頭にいちばん大きな変化 / ユーザーの言葉で / 「バグ修正と安定性向上」だけにしない / 長さの目安）
- プロモーションテキストの使いどころ（170 字で何を言うか、季節・イベント・新機能の告知に使う例）
- Apple の審査で弾かれる表現（「No.1」「最高の」「今すぐダウンロード」等の煽り、検証できない実績、他社名・他プラットフォーム名への言及、価格や特典の誤解を招く表現）
- 検索最適化の観点: 概要本文はインデックスされない（キーワードは別欄）とされる一方、プロモーションテキストや最新情報がインデックスされるかの現時点の通説。確定していない点は「未確定」と明記する

調査結果は箇条書き 10〜15 行以内にまとめ、各行に出典 URL を添えてください。長い引用はしない。

## 2. プロダクト（事実。ここに書いていない機能を創作しないこと）

Toopdbq（トゥーぷどぅっく） — 地理コミュニティ型のソーシャルアプリ。iOS / Android。

解こうとしている問題は一言で「距離が近いのに、情報が遠い」。すぐ近くで面白いことが起きていても、既存の SNS では届かない。マッチングアプリのようなスワイプやプロフィール診断はなく、「今いる場所」と「今日のお題」をきっかけに人と繋がる。

### 仕組み（現行の実装）

1. サークル — 地図上に引かれた円のエリア（例: 「渋谷スクランブル」= スクランブル交差点周辺、駅前・公園・フェス会場・キャンパスなど）。そのエリアの中にいる人だけが投稿できる。外にいる人は閲覧のみ。位置情報そのものは公開されない。エリア外から投稿しようとすると「エリアまで ○ km」と距離が出る。
2. ホーム = サークルのタイムライン — 上半分が正方形の地図、その下にそのサークルの投稿が並ぶ。地図にはサークルのエリア（光る壁の円）とサークル名、そして投稿に紐づいた「場所」が写真ピンで常に貼られている。フィードをタップ／スクロールすると地図が畳まれて全画面のタイムラインになる。左右スワイプで隣のサークルへ。投稿は「まだ見ていないもの」が優先で並ぶ。
3. 投稿 — 写真・動画（撮ったその場で）＋キャプション＋リンク 1 本。Google マップのリンクを貼ると、その投稿は「場所」に紐づく。同じ店・同じスポットの投稿は、投稿者やサークルが違っても 1 つの場所にまとまる。
4. 場所モード — 投稿の Google マップカード、または地図の写真ピンをタップすると、地図がその場所を中心に寄り、吹き出しカード（店の写真・名前・住所・営業中 / 営業時間外・★評価・「Google Mapsで開く」）が出て、下にはその場所の投稿だけが集まった一覧が出る。一覧の横スワイプで「いちばん近い、まだ見ていない場所」へ次々に渡れる。
5. 全画面表示 — タイムラインの写真・動画をタップすると全画面に広がる。縦スワイプで 1 件ずつ、動画は音つき。いいね／コメント／共有。
6. クエスト（お題） — サークルが「今日のお題」を 1 つ出す（例: 「ウィンクして」「スクランブル交差点を渡る」「路地裏のうまい一杯」）。メンバーはそのエリアの中で撮った写真・動画でだけお題に答えられる。自分が出すまで、他の人の答えはぼかされて見えない。出した瞬間に全部ひらく。お題は日替わり。過去のお題にもあとから投稿できる。
7. クエストボード — タイムラインの中に「その日のお題と、みんなの答え」がタイル状に並ぶ。タイルをタップすると地図が上から降りてお題が拡大する。
8. Google マップからの共有 — Google マップの「共有」から Toopdbq を選ぶと、そのリンクを持ったまま撮影して投稿するか、自分の既存の投稿にリンクをつけるか選べる。
9. 投稿は消えない（永久保存）。その場所・そのサークルの履歴が積み上がる。いいね・コメント・共有・1:1 メッセージ・プロフィール・Instagram リンクがある。
10. 位置許可はあとから。許可前は投稿ボタンが「チェックイン」になり、押した時に初めて OS の許可ダイアログが出る。

### 今回のバージョンで入った新機能（最新情報の題材。この 4 つを中心に書く）

- 地図つきホーム: ホームの上半分がサークルの地図になり、投稿に紐づいた場所が写真ピンで見える
- 場所でまとまる投稿・場所モード: Google マップのリンクをつけた投稿が同じ場所ごとにまとまる。ピンや場所カードをタップすると店の情報とその場所の投稿を一覧できる
- 投稿の全画面表示: 写真・動画をタップすると全画面に広がり、縦スワイプで次へ。動画は音つき
- Google マップからの共有: Google マップの「共有」から Toopdbq を選び、場所のリンクを引き継いで投稿できる（既存の投稿にリンクを足すこともできる）

### 参考: 現在ストアに載っている概要（ja。トーンと構成の参考。事実は上の「仕組み」を優先する）

```
近くにいる人と、今日のお題をきっかけに出会う。スワイプも、プロフィール診断もない。

同じ場所で同じことをやった人にだけ、投稿がひらく。話のきっかけが先にあるから、初めましてでも自然に繋がる。位置情報は他の人には見えません。

■ サークルに入る
地図上のエリア（駅前、公園、フェス会場、キャンパス）がサークルです。圏内の人だけが投稿でき、外からは閲覧だけ。正確な位置は他のユーザーに見えません。

■ 今日のお題に答える
「今日いちばんの笑顔」「路地裏のうまい一杯」など、その場所だけのクエストが出ます。エリア内で撮った写真や動画で答えます。

■ 出すまで、見えない
他の人の投稿は、自分が答えるまでぼかされています。投稿した瞬間に全員の答えがひらく。見る人ではなく、やる人になる設計です。

■ その場所の記録が残る
投稿は24時間で消えません。一度答えたサークルなら、過去のお題も見返せます。場所の歴史が、少しずつ積み上がっていきます。

マッチングしない。今いる場所で、同じお題をやる人と出会う。トゥープドゥック（Toopdbq）は、近くにいる人と今日を共有するためのアプリです。
```

### 参考: 最新情報の下書き（前回分。今回は上の「新機能」4 つを主役にして書き直す）

```
今日のお題（クエスト）を、サークルの中心に置きました。エリア内で写真を投稿すると、他の人の答えがひらきます。位置情報は公開しません。
```

### 言葉づかいの決まり

- ユーザー向けには「投稿」と呼ぶ。「ストーリー」とは絶対に呼ばない（24 時間で消える印象を与えるため。実際は永久保存）。
- 「サークル」「クエスト / お題」「場所」「この場所」はアプリ内の用語なのでそのまま使ってよい。
- 英語では circle / quest / post / place。story は使わない。
- 英字のタイトル・見出しは全部大文字にしない（Freedom / not FREEDOM）。
- アプリ名の表記: 日本語文中は「Toopdbq（トゥーぷどぅっく）」、英語は「Toopdbq」。

## 3. 英訳するポスターのコピー（日本語が確定版）

各面: sub（見出しの上の補足 1 行）→ headline（2 行）→ accent（headline の中で色を変える 1 語）。

| # | 画面 | sub | headline | accent |
|---|---|---|---|---|
| 01 | ホーム（地図 + 投稿） | 地図でつながる街の投稿 | この街、／何がある？ | この街 |
| 02 | 場所モード（店のカード + その場所の投稿） | 同じ場所の投稿が集まる | 気になる店の／雰囲気まで。 | 雰囲気 |
| 03 | クエストボード（お題「ウィンクして」+ みんなの投稿） | 投稿すると答えが見える | 同じお題で、／街とつながる | お題 |
| 04 | 全画面表示（動画 + いいね・コメント・共有） | 投稿をタップして全画面へ | 写真も動画も／その場に浸る | 浸る |

英語版の制約:
- headline は 2 行。1 行は スペース込み 14 文字以内（Inter 900・42px で 392px 幅に収める）。3 行にしない。
- sub は 1 行・30 文字以内。
- accent は headline に実在する 1 語（または 2 語の句）をそのまま抜き出す。
- 直訳しない。同じ意図（その面が約束する体験）を英語の自然な言い回しで言い直す。画面に映っているものと食い違う見出しにしない。
- 検索されうる語（nearby, local, map, place, quest, post）を無理のない範囲で混ぜる。

## 4. 書くもの（ja / en 両方）

### A. 調査サマリ
第 1 章の項目を箇条書き 10〜15 行・出典つきで。

### B. ポスター英語版コピー
第 3 章の 4 面ぶん。

### C. 概要（description・4000 文字以内）
- 冒頭 3 行だけで「何のアプリか」「何が新しいか」「誰向けか」が分かる構成にする（「もっと見る」の前で勝負が決まる）。
- 参考の概要の構成（1〜2 行の導入 → ■ 見出し 4〜5 本 → 締めの 1 段落）は踏襲してよいが、今回の新機能（地図つきホーム・場所でまとまる投稿・全画面・Google マップ共有）を必ず盛り込み、クエストと同じ重みで扱う。
- 「機能の説明」ではなく「体験の約束」で書く。各 ■ は 2〜3 文。
- ja と en は別々に書く。en は ja の直訳にしない。

### D. 最新情報（What's New・4000 文字以内）
- 先頭にいちばん大きな変化（地図つきホーム / 場所）を置く。■ 見出しで 4 項目、各 2〜3 行。最後に 1 行で安定性改善に触れてよい。

### E. プロモーションテキスト（170 文字以内・ja / en それぞれ）
- 概要の上に出る 1 段落。今回の新機能を軸に、続きを読ませる一言。文字数を数えて超過しないこと。

## 5. 制約

- 煽らない。「今すぐダウンロード」「No.1」「最高の」「革命的」「話題の」等は使わない（Apple 審査で弾かれる）。
- 実証できない数字・実績を書かない（ユーザー数・ランキング・「○万人」等は禁止）。
- 上の「仕組み」に書かれていない機能を書かない。AR・AI・マッチング・クーポン・予約等の語を勝手に足さない。
- 他社サービス名は「Google マップ」（機能として実在する連携）以外は出さない。
- 各枠 1 案に決め切る。文字数はすべて出力前に自分で数えて、超過がないことを確認する。

## 6. 出力形式

A は Markdown（見出し `##`）、B〜E は次の JSON をコードブロックで。説明文・前置きは付けない。

```json
{
  "poster_en": [
    { "order": 1, "key": "home",  "headline": "", "accent": "", "sub": "" },
    { "order": 2, "key": "place", "headline": "", "accent": "", "sub": "" },
    { "order": 3, "key": "board", "headline": "", "accent": "", "sub": "" },
    { "order": 4, "key": "full",  "headline": "", "accent": "", "sub": "" }
  ],
  "metadata": {
    "ja": { "promotional_text": "", "whats_new": "", "description": "" },
    "en": { "promotional_text": "", "whats_new": "", "description": "" }
  }
}
```

`headline` の改行は `\n` で表す。`description` / `whats_new` の改行も `\n`。
