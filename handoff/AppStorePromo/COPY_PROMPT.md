# コピーライティング用プロンプト（別モデルへ渡す・v6）

`Poster.html`（tall set）の面構成とコピーを別モデル（ChatGPT / web 検索あり）に考えさせる自己完結プロンプト。
「App Store スクショの構成」「興味を惹く文言」の調査 → 構成案 → コピー生成までを 1 回で命令する。
このファイルの `---` 以下をそのまま貼る。旧 v4（Quest 6 面 + メタデータ）は git 履歴を参照。

---

あなたはモバイルアプリの App Store ページ最適化（ASO）とスクリーンショット制作を専門にするコピーライター兼クリエイティブディレクターです。日本語と英語の両方を、それぞれのネイティブが「翻訳臭くない」と感じる水準で書けます。

やることは 3 段階です。**必ずこの順で、1 回の回答の中で全部やってください。**

1. **調査**（web 検索を使う）: App Store スクリーンショットの「構成」と「惹きつける文言」のベストプラクティスを調べる
2. **構成案**: 調査結果を、このアプリの画面素材に当てはめて面の順番・役割・レイアウトを決める
3. **コピー**: 各面の見出し・補足を ja / en で書く

## 1. 調査で明らかにすること

検索して、根拠（URL）つきで要点をまとめてください。一般論の羅列ではなく「このアプリの判断に使える形」に落とします。

**A. 構成（レイアウト・順番）**
- App Store の検索結果とプロダクトページで**最初に見える 1〜3 枚目**の扱い（何を置くと閲覧→インストールが伸びるか。数字が出ている調査があれば引用）
- 「1 面 1 メッセージ」「コピーは上・画面は下」「文字サイズ」「読める語数」など、スマホの一覧サムネイル（縦 3 枚並び）で読めるための定石
- 面数の目安（4 面で足りるか、5〜6 面のほうが有利か）と、後半の面に置くべき内容（機能説明 / 社会的証明 / 使い方 など）
- **Apple の審査ルール**（App Review Guideline 2.3.3・スクショに関する規定）。特に「実際のアプリ画面を使う」「切れた UI・部分拡大 UI の禁止」「マーケ素材が画面より大きいと弾かれる」の扱い。デバイス枠（筐体）を描くことの可否と、画面の下端を面の外に抜く構図の可否
- 日本市場向けスクショで通用している言い回し・構図の傾向（縦書き・キャッチ＋サブの 2 段・など）

**B. 惹きつける文言**
- 一覧のサムネイルで指を止めさせる見出しの型（ベネフィット先行 / 疑問形 / 具体的な状況 / 数字 / 対比 など）と、それぞれが効く条件
- SNS・位置情報・ローカルコミュニティ系アプリ（例: BeReal、Snapchat Map、Yelp、Google Maps、Instagram のスクショなど）が実際に使っている見出しの傾向。真似ではなく「何を約束しているか」を抽出する
- 「機能の説明」ではなく「体験の約束」で書く方法、および Apple がスクショの文字を OCR して検索インデックスに使う件への対応（検索されうる語を自然に混ぜる）

調査結果は **箇条書き 10〜15 行以内**にまとめ、各行に出典 URL を添えてください。長い引用はしない。

## 2. プロダクト（事実。ここに書いていない機能を創作しないこと）

**Toopdbq（トゥーぷどぅっく）** — 地理コミュニティ型のソーシャルアプリ。iOS / Android。

解こうとしている問題は一言で「**距離が近いのに、情報が遠い**」。すぐ近くで面白いことが起きていても、既存の SNS では届かない。既存 SNS は「見せる」ために設計されていて、「一緒にやる」「その場所に行く」ためには設計されていない。

中核の考え: 街のエリアごとに、そこにいる人たちの「今」と「場所」が積み上がる場所をつくる。

### 仕組み（現行の実装）

1. **サークル** — 地図上に引かれた円のエリア（例: 「渋谷スクランブル」= スクランブル交差点周辺、駅前・公園・フェス会場・キャンパスなど）。**そのエリアの中にいる人だけが投稿できる**。外にいる人は閲覧のみ。位置情報そのものは公開されない。エリア外から投稿しようとすると「エリアまで ○ km」と距離が出る。
2. **ホーム = サークルのタイムライン** — 白地のライトな画面。**上半分が正方形の地図**、その下にそのサークルの投稿が並ぶ。地図にはサークルのエリア（光る壁の円）とサークル名、そして**投稿に紐づいた「場所」が写真ピンで常に貼られている**。フィードをタップ／スクロールすると地図が畳まれて全画面のタイムラインになり、先頭から引き下げると地図が戻る。**左右スワイプで隣のサークルへ**移る。投稿は「まだ見ていないもの」が優先で並ぶ。
3. **投稿** — 写真・動画（撮ったその場で）＋キャプション＋**リンク 1 本**。リンクは OGP カードで表示される。**Google マップのリンクを貼ると、その投稿は「場所」に紐づく**。同じ店・同じスポットの投稿は、投稿者やサークルが違っても 1 つの場所にまとまる。
4. **場所モード（リンクモード）** — 投稿の Google マップカード、または地図の写真ピンをタップすると、**地図がその場所を中心に寄り、吹き出しカード**（店の写真・名前・住所・営業中 / 営業時間外 / 24 時間営業・★評価・「Google Mapsで開く」ボタン）が出て、**下にはその場所の投稿だけが集まった一覧**が右からスライドインする。地図を指でずらすと近くの別のピンが選ばれ、一覧の横スワイプで「いちばん近い、まだ見ていない場所」へ次々に渡れる。
5. **全画面表示** — タイムラインの写真・動画をタップすると、その投稿が**行の矩形から全画面へ広がる**。縦スワイプで 1 件ずつスナップ、動画は音つき。右側にいいね／コメント／共有、下に投稿者とキャプション。横スワイプで隣のサークルへ。場所モードからなら、全画面のまま次の場所へ渡れる。
6. **クエスト（お題）** — サークルが「今日のお題」を 1 つ出す（例: 「渋谷で乾杯」「路地裏のうまい一杯」「オーリー」）。メンバーは**そのエリアの中で撮った写真・動画でだけ**お題に答えられる。**自分が出すまで、他の人の答えはぼかされて見えない**。出した瞬間に全部ひらく。お題は日替わり。過去のお題にもあとから投稿できる。
7. **クエストボード** — タイムラインの中に「その日のお題と、みんなの答え」がタイル状に並ぶボードとして混ざる（タイルをタップすると地図が上から降りてお題が拡大）。地図の左下のボタンで**「クエストボード」モード**（縦 = サークル、横 = そのサークルのお題の一覧）に切り替わる。
8. **Google マップからの共有** — Google マップの「共有」から Toopdbq を選ぶと、**そのリンクを持ったまま撮影して投稿**するか、**自分の既存の投稿にリンクをつける**か選べる。
9. 投稿は消えない（永久保存）。その場所・そのサークルの履歴が積み上がる。いいね・コメント・共有・1:1 メッセージ・プロフィール（自分のタイムライン）・Instagram リンクがある。
10. 位置許可はあとから。許可前は投稿ボタンが「チェックイン」になり、押した時に初めて OS の許可ダイアログが出る。

### 言葉づかいの決まり

- ユーザー向けには「**投稿**」と呼ぶ。「ストーリー」とは絶対に呼ばない（24 時間で消える印象を与えるため。実際は永久保存）。
- 「サークル」「クエスト / お題」「場所」「この場所」はアプリ内の用語なのでそのまま使ってよい。
- 英語では circle / quest / post / place。story は使わない。
- 英字のタイトル・見出しは全部大文字にしない（Freedom / not FREEDOM）。

## 3. 素材（用意できる実機スクリーンショット）

以下の 4 画面は実装済みで、実機スクショを用意できます。**面に載せる画面はこの 4 つだけ**（調査で 5〜6 面が有利と分かった場合は、上の「仕組み」にある画面から追加候補を挙げてよい。ただし未実装の画面は挙げない）。

| key | 画面 | 見えているもの |
|---|---|---|
| `home` | ホーム（サークル「渋谷スクランブル」） | 上半分に正方形の地図（エリアの円・サークル名・場所の写真ピン）、下に投稿のタイムライン、右上に投稿ボタン |
| `place` | 場所モード | 地図がひとつの店を中心に寄り、吹き出しカード（写真・店名・住所・営業中・★評価・Google Mapsで開く）、下にその場所の投稿一覧 |
| `full` | 全画面表示 | 投稿の写真／動画が全画面、右にいいね・コメント・共有、下に投稿者とキャプション |
| `board` | クエストボード | 縦にサークル、横にそのサークルのお題タイルが並ぶ一覧（または、タイムライン内のお題ボードが拡大した状態） |

## 4. 現行のポスター構図（変えてよいが、変えるなら理由を書く）

- iPhone 6.9″ 用 **440×956**（書き出し 1320×2868 @3x）。**黒地**。
- **上 26%（高さ 252px）がコピー帯**: 上段に**補足 1 行**（21px・太字・白）、その下に**見出し 2 行**（極太 900・白・最大 46px）。見出しは全角 1 文字 = 1em で、**1 行が 8 文字なら 46px、9 文字で 42px、10 文字で 38px** と自動で縮む。
- 帯の下に**筐体（ベゼル）つきの実機画面**を置き、**画面の下端は面の外へ抜けて切れる**（上から約 84% が見えている）。
- 以前、別の版で Apple の Guideline 2.3.3 に「**画面が切れている・マーケ素材が画面より大きい**」でリジェクトされたことがある。調査 A の審査ルールと照らして、**この構図のままで通るか、直すべき点があるか**を判定してください。

## 5. 書くもの

### A. 調査サマリ
第 1 章の A / B を箇条書き 10〜15 行・出典つきで。

### B. 構成案
- 面の数と**順番**。各面に `key`（home / place / full / board）、**役割（その面が約束すること）を 1 行**、**選んだ理由を 1 行**（調査のどの知見に基づくか）。
- 1 枚目に何を置くかは特に丁寧に（一覧サムネイルで最初に見える 1〜3 枚が勝負）。
- レイアウトへの指示（コピー帯の位置・文字の大きさ・筐体の扱い・画面の切れ方）を、現行構図との差分として。変えないなら「そのまま」と明記。

### C. コピー（ja / en 両方）
各面につき:
- **headline**: ja は **1 行 9 文字以内 × 2 行**（句読点込み。8 文字以内が理想。3 行にしない）。en は **1 行 3 語まで × 2 行**。
- **sub**: 見出しの上に置く補足 1 行。ja **14 文字以内** / en **7 語以内**。見出しと同じことを言い換えない（見出し = 約束、sub = 状況 or 一言の説得）。
- **accent**: headline の中で色を変えて強調する語を 1 つ（headline に実在する文字列をそのまま抜き出す）。
- **ocr**: その面の headline / sub に含めた「検索されうる語」を列挙（例: 近く, 渋谷, 地図, 投稿 / nearby, map, local）。無理に詰め込まない。
- 1 枚目（フック）だけ、A/B テスト用の第 2 案を添える。

### D. リリースノート（What's New・ja / en）
今回のアップデートで入った機能 = 「地図つきホーム」「Google マップの場所でまとまる投稿・場所モード」「投稿の全画面表示」「Google マップからの共有」を、ユーザー向けに各 2〜3 行。4000 文字以内・■ 見出しで区切る。

## 6. 制約

- **煽らない**。「今すぐダウンロード」「No.1」「最高の」「革命的」「話題の」等は使わない（Apple 審査で弾かれる）。
- **実証できない数字・実績を書かない**（ユーザー数・ランキング・「○万人」等は禁止）。
- 上の「仕組み」に書かれていない機能を書かない。AR・AI・マッチング・クーポン・予約等の語を勝手に足さない。
- ja と en は**別々に書く**。en は ja の直訳にしない（同じ意図を英語の自然な言い回しで言い直す）。
- 機能の説明ではなく体験の約束で書く。ただし画面に映っているものと食い違う見出しにしない（`place` の面で「クエスト」の話をしない、など）。
- 3 案ではなく、**各枠 1 案に決め切る**（フックの第 2 案だけ例外）。
- 文字数はすべて出力前に自分で数えて、超過がないことを確認する。

## 7. 出力形式

A・B は Markdown（見出し `##` 2 つ）、C・D は次の JSON をコードブロックで。説明文・前置きは付けない。

```json
{
  "composition": [
    { "order": 1, "key": "home", "role": "", "why": "" }
  ],
  "layout_changes": [""],
  "panels": [
    {
      "order": 1, "key": "home",
      "ja": { "headline": "", "accent": "", "sub": "", "ocr": [""] },
      "en": { "headline": "", "accent": "", "sub": "", "ocr": [""] }
    }
  ],
  "alt_hook": {
    "ja": { "headline": "", "accent": "", "sub": "" },
    "en": { "headline": "", "accent": "", "sub": "" }
  },
  "whats_new": { "ja": "", "en": "" }
}
```

`headline` の改行は `\n` で表す。`panels` の順番は `composition` と一致させる。
