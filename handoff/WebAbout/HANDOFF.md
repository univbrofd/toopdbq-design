## 何を作るか

`toopdbq.com` のトップ（1 サークルのライブ表示）を **下にスクロールすると現れるサービス説明セクション**。
今日のトップは 100dvh で終わっていて、初見の人はこれが何のサービスか分からないまま離脱する。それを解く 1 セクション。

成果物:

- `handoff/WebAbout/WebAbout-a.html` / `-b.html` / `-c.html` — **3 案**。各案は全章を縦に並べた 1 ページ
- `handoff/WebAbout/WebAbout.css` — **差分だけ**（foundation をコピーしない。案ごとの差分は `-a.css` … でもよい）
- `handoff/WebAbout/gallery.html` — 3 案を並べて比べる
- `_ds_manifest.json` に `group="WebAbout"` で登録（既存 37 枚のカードは消さない）
- 最終はダウンロード可能な bundle

各案の冒頭に **既存トップの下端 → About の継ぎ目**を必ず含める（`shots/current-top.jpg` を上に敷いてから自案が始まる形）。継ぎ目の設計がこの依頼の半分。

## 絶対に守る契約（破ると実装に載らない）

- **vanilla HTML/CSS のみ。** 実装先は素の静的 1 ファイル（`public/index.html`）。React / Tailwind / CDN / 外部 JS / ビルド前提の記法は使えない
- **JS を使うなら IntersectionObserver だけ・3KB 以内。** `animation-timeline: view()` は `@supports` でくるみ、非対応でも**静止で成立**すること。`prefers-reduced-motion: reduce` で全アニメ停止
- **初回ペイント時に画面サイズの `position:fixed` を置かない。** iOS Safari は「バー裏まで描くか」をロード時のページ状態で決めて固定する。全画面 fixed があると黒帯になる（`.claude/rules/web.md` の実測結果）
- アセットは共有だけ: `../../assets/icons/`、`../../assets/images/`、`../../assets/sample/{reel,user,uv,background}/`。**絵文字なし**
- 画像は `loading="lazy" decoding="async"`。実装時は `media.toopdbq.com` の 4 バケット（w160 / 384 / 640 / 1080）に載るので、**1 枚に 2 種類の表示幅を混ぜない**
- **ライト面**（現行トップの白地の続き）。ダーク反転しない。ただし写真・地図の上は必ずスクリム
- 呼称固定: **投稿**（ストーリーと呼ばない）／**サークル**／**クエスト**（＝お題）／**輪**
- コピーは下の全文を**一字一句このまま**。改行位置・強調は磨いてよいが、語を足さない・言い換えない
- 日本語のみ。英語版は今回作らない
- **既存トップ（map-panel / strip-title / quest board）は再設計しない。** 触るのは赤線から下だけ

## コピー（一字一句このまま）

### ヒーロー

> クエストって、なに？

> Toopdbq は、いま自分がいる場所で、まわりにいる人と友達になるためのアプリです。

### 1. サークルは、地図の上にある「輪」

> サークルは、地図の上にかかれた輪のことです。駅の前、公園、お祭りの会場、学校のまわり。どこにでも作れます。誰かが「ここにサークルを作ろう」と決めると、その場所に輪ができます。

### 2. その輪から、お題が出ます

> 輪には、お題が出ます。これをクエストと呼びます。

例示（参考紙面では Q バッジ付きの囲み）:

> たとえば「今日いちばんの笑顔の写真」。たとえば「路地裏のおいしい一杯」。お題はその場所だけのもので、ほかの場所には出ません。

### 3. 答えられるのは、輪の中にいる人だけ

> ここが、このアプリでいちばん変わっているところです。
>
> クエストに答えられるのは、いま本当にその輪の中にいる人だけ。家から見ているだけの人は、答えられません。
>
> だから答えが集まったとき、そこに並んでいるのは「同じ時間に、同じ場所にいた人たち」だけになります。

### 4. 答えかたは、カメラで撮るだけ

> むずかしいことはありません。
>
> お題に合う写真か動画を、その場でカメラで撮ります。撮れたら、投稿します。それだけでクエストは達成です。

### 5. 自分が出すまで、ほかの人の答えは見えません

> 投稿する前は、ほかの人の写真にはぼかしがかかっていて、何が写っているかわかりません。
>
> でも、自分が1枚出したしゅんかん、ぼかしが消えます。その日その場所にいた全員の答えが、いっせいにひらきます。
>
> これは意地悪をしているのではありません。見ているだけの人ばかりになると、だんだん誰も出さなくなってしまうからです。1枚出した人だけが、みんなの1枚を見られる。おたがいさま、という決まりです。

### 6. ひらいたら、「いいね」が押せます

> ひらいた写真の中に、きっと気になる1枚があります。そこに「いいね」を押してください。
>
> 知らない人にいきなり話しかけるのは、大人でもむずかしいことです。でも「いいね」なら押せます。
>
> 相手には、同じお題に答えた人からいいねが来たことが伝わります。おたがいに「同じ場所にいたんだ」とわかるので、そこから話が始めやすくなります。
>
> メッセージが続いて、次に会う約束になることもあります。知らない人が、話せる相手に変わっていきます。

### 7. あなたがどこにいるかは、ほかの人には見えません

> 位置情報は、2つのことにしか使いません。
>
> - 近くにサークルがあるかを探すため
> - いま輪の中にいるかを確かめるため
>
> あなたの現在地が、地図の上にほかの人へ表示されることはありません。

### 8. つくった人から

> 大学のサークルを思い出してみてください。入った日はただの他人だったのに、いっしょに何かをしているうちに、いつのまにか友達になっている。あの気軽さが、世界中のどこにでもあったらいいのに。そう思ってこのアプリを作っています。
>
> 小さな村では、住んでいる場所が同じというだけで、人は自然と話すようになります。買い物に行けば顔を合わせるし、道ですれちがえば挨拶をします。
>
> でも、都会ではそれが起きません。人が多すぎるからです。同じ駅を毎日使って、同じ店に通っていても、話したことは一度もない。きっかけがないまま、たぶん一生交わらない。それは、もったいないことだと思いました。
>
> 友達になるために必要なのは、自己紹介ではないと思っています。必要なのは、いっしょに何かをすることです。同じことをやった人どうしなら、話すことが最初からあります。
>
> だから、みんなで取り組めるお題をつくりました。それがクエストです。同じ場所にいるだけだった人が、同じお題に答えた人になる。そこから話が始まる。それが世界のあちこちで起きたら、世界はもう少しフレンドリーになるはずです。テクノロジーには、それができると思っています。

### クロージング

> 同じ場所にいるだけだった人が、同じお題に答えた人になる。
>
> Toopdbq は、そのきっかけをつくるアプリです。

## 3 案は探索軸を散らすこと（似た案を 2 つ出さない）

| 案 | 軸 | 縛り |
|---|---|---|
| **A 読み物** | 文が主・図が従。静かで長い。章間は余白と細い罫だけ | 画面いっぱいの図を使わない。1 章 = 1 スクリーン未満。8 章を続けて読ませる |
| **B スクロールテリング** | 図が主・文が従。1 章 = ほぼ 1 画面。スクロールで図が変化する（ぼかしが取れる / 輪が閉じる / いいねが飛ぶ） | 変化は CSS のみ or IO で class を足すだけ。非対応環境で**静止しても意味が通る**こと |
| **C 紙面カード** | 参考紙面をそのまま web に。番号バッジ + カードの積層。密度が高く一望できる | 402px 幅で「右に図」が成立するレイアウトを作る（紙面の横並びをそのまま縮めない） |

3 案とも: 全 8 章 + ヒーロー + クロージングを含む。章 5（ぼかし → ひらく）の図は必ず作る。継ぎ目（現行トップ下端 → About）の解を必ず持つ。

## 置かないもの

- デーティングアプリの記号（顔を向かい合わせる / 中央のハート / マッチ / 性別・年齢・距離 / 人をスワイプ）。`handoff/Onboarding/HANDOFF.md` と同じ禁止
- 効果の 3 盛り（枠 + 影 + グラデを同時に足さない）
- 絵文字・ストックイラスト・新規の AI 生成画像
- 白地に置いた白アイコン / 白バラロゴ（実測 6・7）
- 不要な中央寄せ（長文は左揃え）
- 数字の飾り（「10,000 人が利用」等、事実でない社会的証明）

## ★ 判断が要るフラグ（握りつぶさず、案の中で扱うこと）

1. **CTA**。App Store は審査中・Google Play は未公開で、**今はストアリンクを張れない**。クロージング下の CTA を「置かない」「文言だけ置いてリンクは後で差す」「上のトップへ戻す」のどれにするか、案ごとに違う答えを出す
2. **クロージングの一文**。「Toopdbq は、そのきっかけをつくるアプリです。」は参考紙面から採った文で、支給テキストには無い。採用してよいか案の中で提示する
3. **「つくった人から」の顔**。参考紙面には人物イラストがあるが、DS には実写真プールしかなく、本人写真も無い。顔を置くか / 置かないかを案ごとに決める（置くなら**イラストは禁止**なので別解を出す）
4. **長さ**。支給テキスト全文（約 1,700 字）を全部読ませるか、章 8 を折りたたむか。トップの下の読み物としてどこまで許容できるかを案の差として出す
